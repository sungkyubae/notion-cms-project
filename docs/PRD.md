# PRD: 매매 일지 블로그

## 1. 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| 프로젝트명 | 매매 일지 블로그 |
| 목적 | Notion을 CMS로 활용한 개인 주식 매매 기록 공개 블로그 |
| 핵심 가치 | 매수·매도 내역과 매매 근거를 Notion에 기록하면 웹에 타임라인 형태로 자동 게시되어, 투자 판단을 돌아보고 복기하는 데 활용 |
| CMS 선택 이유 | Notion API를 활용하여 비개발자도 콘텐츠를 관리할 수 있음 |

## 2. 목표 및 비목표

### 목표
- Notion에 기록한 매매 내역이 별도 배포 없이 웹에 자동 반영된다.
- 매매 근거(차트 이미지, 메모 포함)를 읽기 좋은 형태로 공개한다.
- 매수/매도 구분으로 기록을 빠르게 좁혀 볼 수 있다.

### 비목표 (MVP 제외)
- 손익 계산
- 차트·통계
- 검색
- 댓글
- 인증

## 3. 주요 기능

| # | 기능 | 설명 |
| --- | --- | --- |
| 1 | 매매 기록 목록 | 공개 처리된 기록을 최신순 카드 형태로 표시 (종목명, 매수/매도 구분, 가격, 수량, 날짜, 태그) |
| 2 | 매매 기록 상세 | Notion 페이지 본문(매매 근거, 차트 이미지, 메모)을 블록 단위로 렌더링 |
| 3 | 필터링 | 매수/매도 구분, 태그별로 목록 필터링 |

> MVP에서는 매수/매도 구분 필터만 구현하고, 태그 필터는 MVP 이후 단계에서 추가한다. (7장 참고)

## 4. 기술 스택

| 영역 | 기술 | 비고 |
| --- | --- | --- |
| Frontend | Next.js 16 (App Router), React 19, TypeScript | 요청서는 Next.js 15였으나 프로젝트에 설치된 버전(16.3.8)을 따름 |
| CMS | Notion API (`@notionhq/client`) | 아직 미설치 |
| Styling | Tailwind CSS v4, shadcn/ui | 스타일은 `base-nova` (`@base-ui/react` 기반) |
| Icons | Lucide React | |
| 배포 | Vercel | |

### 기술 메모
- shadcn `base-nova`는 Radix의 `asChild` 대신 `render` prop을 사용한다. (예: `<DropdownMenuItem render={<Link href="/" />}>`)
- shadcn 컴포넌트는 직접 작성하지 않고 `npx shadcn@latest add <이름>`으로만 추가한다.
- 이 Next.js 버전은 기존 지식과 다를 수 있으므로 코드 작성 전 `node_modules/next/dist/docs/`를 확인한다.
- 포맷: 들여쓰기 2칸, 세미콜론 없음, 큰따옴표.

## 5. Notion 데이터베이스 구조

| 속성명 | 타입 | 설명 | `Trade` 필드 |
| --- | --- | --- | --- |
| 종목명 | Title | 종목 이름 (예: 삼성전자) | `name` |
| 티커 | Text | 종목 코드 (예: 005930) | `ticker` |
| 구분 | Select | 매수 / 매도 | `type` (`"buy"` \| `"sell"`) |
| 가격 | Number | 체결 단가 (원) | `price` |
| 수량 | Number | 체결 수량 (주) | `quantity` |
| 날짜 | Date | 체결일 | `date` |
| 태그 | Multi-select | 매매 전략·섹터 (예: 스윙, 장기, 반도체, 실적) | `tags` |
| 공개 | Checkbox | 체크된 기록만 웹에 노출 | (쿼리 필터로만 사용) |
| 한줄 요약 | Text | 목록 카드에 표시할 매매 이유 요약 | `summary` |
| (페이지 본문) | - | 상세 매매 근거, 차트 캡처, 복기 메모 | `getBlocks`로 별도 조회 |

- 총액은 저장하지 않고 `price × quantity`로 계산한다.
- Notion 속성 → `Trade` 변환은 `lib/notion.ts`의 매핑 함수 한 곳에서 처리한다.

## 6. 화면 구성

### 6.1 메인 (`/`)
- 매매 기록 카드 목록
- 상단: 매수/매도 탭, 태그 필터
- 카드 구성
  - 구분 배지: 매수 = 빨강, 매도 = 파랑
  - 종목명 · 티커
  - 가격 × 수량 = 총액
  - 날짜
  - 한줄 요약
  - 태그

### 6.2 상세 (`/trades/[id]`)
- 상단: 매매 정보 요약 박스 (구분, 가격, 수량, 총액, 날짜, 태그)
- 하단: Notion 본문 블록 렌더링
- "목록으로 돌아가기" 버튼

### 6.3 공통 상태
- 로딩, 빈 상태(공개된 기록 없음), 404(존재하지 않거나 비공개인 기록)

## 7. MVP 범위

| 항목 | 내용 |
| --- | --- |
| 데이터 조회 | `공개 = true`인 기록만 날짜 내림차순으로 조회 |
| 화면 | 메인 목록 페이지 + 상세 페이지, 2개 |
| 필터 | 매수/매도 구분 (URL 쿼리 파라미터 기반, 예: `/?type=buy`) |
| 본문 블록 | 문단, 제목, 리스트, 이미지, 인용 |
| 갱신 | ISR (`revalidate` 60초)로 Notion 수정 내용 자동 반영 |
| 레이아웃 | 반응형 (모바일 1열 / 데스크톱 2~3열) |
| 제외 | 손익 계산, 차트·통계, 검색, 댓글, 인증 |

태그 필터는 기능 3에 포함되나 MVP 이후로 미룬다. MVP에서는 카드에 태그를 표시하기만 한다.

## 8. 아키텍처 및 데이터 흐름

```
Notion DB ──(Notion API)──> lib/notion.ts ──> 서버 컴포넌트 ──> 페이지 (ISR 60초)
```

### 데이터 레이어 (`lib/notion.ts`)
| 함수 | 역할 |
| --- | --- |
| `getTrades(type?)` | 공개 기록 목록 조회 (날짜 내림차순, 구분 필터 선택) |
| `getTrade(id)` | 단건 조회 (비공개이면 `null` → 404) |
| `getBlocks(id)` | 페이지 본문 블록 조회 |
| 매핑 함수 | Notion 속성 → `Trade` 변환 |

### 컴포넌트
- `TradeCard`: 목록 카드
- `NotionBlocks`: 블록 렌더러 (문단, 제목, 리스트, 이미지, 인용)
- 상세 요약 박스
- 컴포넌트 계층 규칙(`ui` → `common` → `layout` → `sections`)을 따른다.

### 라우팅
- 목록/상세 페이지가 속할 라우트 그룹(기존 `(marketing)` 재사용 또는 신규 그룹)은 구현 시 결정한다.
- 상세 페이지는 `generateStaticParams`로 정적 경로를 생성한다.

## 9. 환경 변수

`.env.local`에 설정하고 저장소에 커밋하지 않는다. Vercel에는 프로젝트 환경 변수로 동일하게 등록한다.

| 이름 | 설명 |
| --- | --- |
| `NOTION_TOKEN` | Notion 통합(Integration) 시크릿 |
| `NOTION_DATABASE_ID` | 매매 기록 DB ID |

## 10. 구현 단계

- [ ] **1. Notion 준비**: 통합 생성 → DB 생성 및 속성 설정 → DB 페이지에서 "연결 추가"로 통합 연결 → 샘플 기록 3~5개 입력
- [ ] **2. 프로젝트 셋업**: shadcn/ui 컴포넌트 추가(card, badge, tabs, button), `@notionhq/client` 설치, `.env.local`에 `NOTION_TOKEN`·`NOTION_DATABASE_ID` 설정 (Next.js 프로젝트와 Tailwind는 이미 구성됨)
- [ ] **3. 데이터 레이어**: `lib/notion.ts`에 `Trade` 타입, `getTrades`, `getTrade`, `getBlocks`, 속성 매핑 함수 작성
- [ ] **4. 목록 페이지**: 서버 컴포넌트에서 `getTrades` 호출, `TradeCard` 작성, 매수/매도 탭 필터 연결
- [ ] **5. 상세 페이지**: `generateStaticParams`로 정적 경로 생성, 요약 박스 + `NotionBlocks` 작성
- [ ] **6. 마무리**: `revalidate` 설정, 로딩/빈 상태/404 처리, 메타데이터(title·description) 설정, Vercel 배포

## 11. 비기능 요구사항

- **성능**: ISR로 Notion API 호출을 최소화한다. 이미지는 `next/image`를 사용한다.
- **반응형**: 모바일 1열, 데스크톱 2~3열.
- **접근성**: 배지는 색상에만 의존하지 않고 "매수"/"매도" 텍스트를 함께 표시한다.
- **오류 처리**: Notion API 실패 시 전역 `error.tsx`, 존재하지 않는 기록은 `not-found.tsx`로 처리한다.
- **SEO**: 페이지별 `title`·`description` 메타데이터를 설정한다.
- **보안**: `NOTION_TOKEN`은 서버에서만 사용하며 클라이언트 번들에 노출하지 않는다. 비공개 기록은 목록·상세 모두에서 접근할 수 없어야 한다.

## 12. 리스크 및 고려사항

| 리스크 | 대응 |
| --- | --- |
| Notion 파일(이미지) URL이 약 1시간 후 만료됨 | ISR 60초 재검증으로 완화하고, `next/image` 원격 도메인 설정을 확인 |
| 상세 `id`로 직접 접근 시 비공개 기록 노출 | `getTrade`에서 `공개` 값을 검증하고 아니면 404 |
| Notion API 호출 제한(rate limit) | ISR 캐싱으로 호출 빈도를 낮춤 |
| 지원하지 않는 블록 타입 | 알 수 없는 블록은 건너뛰고 오류로 중단하지 않음 |
